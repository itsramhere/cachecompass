# Independent Phase 4 measurement protocol

Frozen 2026-10-19 UTC before the independent confirmation matrix. The pilot IDs `p4review_pilot_cal24_20261019` and `p4review_pilot_immediate_20261019` are implementation checks, excluded from confirmation. This supersedes the submission protocol, without deleting its measurements. No Phase 5 work is authorized by this document.

Use `configs/phase4_review.yaml`: 512 immutable 1024-byte objects, seed 404, 64 rendezvous buckets, two old Redis processes and an empty third process. PostgreSQL executes an indexed lookup plus the same deliberately artificial 20,000-round SQL MD5 workload. This is real constrained database CPU work; it is not a production query distribution. Compose enforces PostgreSQL 1 CPU/512 MiB and each Redis 0.5 CPU/128 MiB with 32 MiB allkeys-LRU. Record actual container limits and cgroup CPU usage/throttling, not just nominal settings. The relation is small and expected buffered; the retained original buffer probe is descriptive only. No disk-capacity claim.

Each run physically recreates the label-verified disposable project. All physical caches must be empty with zero evictions and distinct process IDs before preparation. The complete deterministic dataset is placed on old owners, with every initial payload and key verified. Complete authoritative DB hashes/checksum and final pre-event physical state are checked. Four foreground DB connection-preparation queries are explicitly outside measurement. Initial dataset DDL/insertion, verification, cache placement, warm reads and post-horizon inspections are outside offered demand and are not capacity traffic.

Warm stability is three fixed one-second windows of 36 scheduled old-cache reads/s, using a fixed key prefix. Every read must hit and return the correct payload; each window p95 service latency (high resolution QPC) must be <=100 ms, and max minus min window p95 <=30 ms. No adaptive extension or window deletion. Any failure remains a retained failed preparation, requiring a fresh explicitly linked repetition. These thresholds acknowledge the Windows timer/scheduler environment; stability is operational and does not establish stationarity in general.

One DB read, one PING and one INFO per cache are sampled every 0.5 s in every measurement, including DB calibration and cache-only headroom runs. Observation uses distinct bounded cache/background DB pools, no driver retries, no catch-up or overlapping rounds. Raw issue/terminal/outcome/reservation records and sampled detail are persisted. Four foreground DB connections and eight foreground cache connections/node are distinct from one background connection per service. Calibration refuses more than one configured foreground DB attempt; expansion uses the same one-attempt database path. Redis driver retries are zero; pool connection establishment attempts are not SQL read attempts. Query transaction setup is part of the measured logical lookup. No unrelated application traffic, discretionary DB warm-up, donor migration, forced deletes, pre-copy or foreground donor fallback occurs. Compose health probes and service background activity remain measured resource interference, not application reads.

Calibration confirmation is three independent physical runs at each offered rate 12, 24 and 36 DB reads/s, each lasting 12 seconds plus a 0.5-second lead-in. All offers and time bins [0.5,4.5), [4.5,8.5), [8.5,12.5) remain included; no calibration request is excluded as warm-up. Rotate rate order across repetitions (12/24/36, 36/12/24, 24/36/12). Persist independent absolute schedules and every terminal row as it occurs; slow completions never postpone later offers. Successful p95/p99 start at scheduled arrival. Every failed, refused, unsubmitted or timed-out offer and every successful latency >100 ms is an all-offer violation. The request timeout remains 1 second, distinct from the provisional 100 ms target.

The provisional empirical C_safe is the highest tested rate with at least three valid same-source/config independent runs, every offer submitted/issued/completed, zero all-offer violations, p95 below 100 ms in every run, and max dispatch lag <=50 ms. If none qualifies, report null and leave capacity gating unmet. This is a duration-limited foreground admission rate conditional on the common probes (roughly 2 additional DB reads/s), query cost, pool/host/quota/target. It is not physical DB peak capacity or a universal sustainable rate. Report connection issue waits, pool maxima, actual attempt counts and CPU quota/throttling to identify client or other limits. Missing offers or dispatch delay beyond the registered limit invalidate capacity inference, not an overload outcome. Queueing at the DB pool under DB overload remains visible in scheduled latency.

Expansion confirmation is three independently recreated control/immediate pairs at 36 application offers/s for 8 s plus the same 0.5 s lead-in. Pair order alternates control/immediate, immediate/control, control/immediate. No outcome-driven repetitions. Dataset, workload seed, relative schedules, initial complete logical contents, limits, foreground semantics and overhead match. Select exactly round(0.8*N) affected offers; sample each stratum by the configured Zipf exponent 1.15. These are independent host/process runs of a deterministic workload, not independent random workload populations.

At origin+3 s, immediate cutover publishes every and only affected bucket through OLD/COPYING/ELIGIBLE/NEW in one epoch, with zero migration work. Record requested/published timestamps, exact bucket IDs, expected/new epochs and path. Control does not publish. Physical destination starts empty and remains unwritten until a foreground miss fills it. Validate captured owner/epoch against submitted time, allowing ambiguous equal coarse ticks to resolve through epoch. Publication more than 50 ms late is invalid. Windows are fixed by scheduled arrival: pre [0,3), transition [3,5), post [5,8.5). Observe to 8.5 s even when all requests or cutover finish earlier, then drain to per-request deadlines/cleanup. A request cohort's attributed DB attempts are not the same quantity as actual issue-time DB pressure; report both in the independent audit.

One separate old-cache control at 144 offers/s profiles the combined router/load generator/Redis/telemetry path above the 36-rps intended workload. Retain it regardless of result; it is a capacity diagnostic, not a fourth confirmation pair. Record process CPU time, high resolution event-loop delay, bounded metric queue/wait, cgroup CPU use/throttling, cache memory/evictions, and dispatch delay. Shared host, Docker networking, timer granularity and probe interference are possible alternative causes. They must be disclosed; a cache-only pass alone does not prove a DB CPU bottleneck.

Validate raw records before inference: schedule identities/uniqueness and chronology, terminal outcomes, payloads, each issued operation/parent/attempt count, separate probe records and horizon, deterministic owner map/publication, complete initial states/fresh processes, artifact/source hashes and recomputed summaries. Invalid runs exit analysis nonzero and are excluded explicitly. Legacy measurements cannot become corrected confirmations by changing labels. Source/config identity is frozen before the matrix; substantive fixes require new linked measurements.

Independent runs/pairs are the replication units. Publish every run's p95, violations, DB work, dispatch delay and fixed time bins. With three pairs, report mean/range and an explicitly exploratory normal-model t interval (df=2); its normal assumption is unverified. No pooled-request confidence intervals, post-hoc exclusions or population-level certainty. A positive reproducible penalty requires cold misses, extra actual DB work and timing evidence plus investigated alternatives. An absent/inconclusive penalty may pass only as an adequately investigated negative characterization; it never establishes room for improvement. Essential missing measurement leaves the gate unmet.

Full wire bytes remain unknown/null. Encoded conservative reservations are charged bounds, not measured wire traffic. SQL server capacity is not inferred from those bytes. Preserve original failures and issue an append-only replacement/exclusion map. Analysis tables and SVG coordinates regenerate from validated raw requests; use a fresh output directory. The review supplies the final gate and handoff, and stops before Phase 5.
